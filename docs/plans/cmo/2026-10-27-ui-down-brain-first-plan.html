UI down, brain first: the plan to build the AI CMO

Status: proposed (2026-10-27), for the owner's review. Markdown twin for agents: 2026-10-27-ui-down-brain-first-plan.md. Built on docs/architecture/workflow.md and the department pages next to it. The screen list for the designer is 2026-10-27-ui-design-brief.md.

1. Owner direction (2026-10-27)

  • Build the brain first, then the rest of the system.
  • Work top-down, from the whole system to the details.
  • Start from the UI: redesign the whole app in Claude Design. The finished design is the goal every build phase works toward.

2. Advisor view

PointView
UI as the goalAgree. Each screen names the data it shows and the actions it offers. That becomes the contract for tables, RPCs and jobs, so nothing gets built that no screen uses. Today's CMO screen already works this way (lib/cmo/workspace.ts with live.* flags).
Brain firstAgree, with one condition. The brain is the spine every department plugs into, and it can be tested on departments that already exist: X posts, the Reddit scan, competitor research, goals and the long take. This changes the owner decision of 2026-10-19 ("the editor is the spearhead"), so the Strategy section of CLAUDE.md changes with this plan (§7).
The one exceptionFinish Studio S0 (long take on production, PR #111) alongside the design work. It is nearly done, it is the first real OpenCMO marketing video, and it gives the brain a real Studio to brief in B3.
Redesign scopeEverything except the inside of the editor. The editor has its own parity work and shortcuts. Redesigning it now would put the brain off by weeks. The editor gets the new design tokens and an entry point from Studio; a redesign inside it comes later.
Claude Design outputA target, not code to paste. We rebuild the screens with our own components and routes, with the same tokens. The design must show real states: empty, loading, waiting on the founder, failed, out of credits. Those states are where the contracts come from.
RiskDesign without data drifts into features we cannot back (the rule is "don't ship coming soon"). Each screen is tagged with the phase that makes it live. The app shows only the screens whose phase has shipped.
