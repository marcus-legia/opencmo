Writer: the words department

Writer writes every word that goes out: posts, captions, video titles and descriptions, the brief a video starts from, the text on slides. It writes in the founder's voice, from the founder's documents, and passes code checks and a second model before a card. Markdown twin for agents: writer.md. Parent pages: ai-cmo.html, brain.html, studio.html. Status: proposed.

Verdict

A strong core, only for X
  • Three versions with different hooks → code checks → a checker on the provider that did not draft → one fix → a card (draft-post.ts).
  • Code checks that cannot be argued with: 280 characters, the strategy's words to avoid, any number of 10 or more must be in the documents, at most two hashtags (check-post.ts).
  • A learning loop no competitor we read shows: every approval records the version chosen, the similarity and an edit mode (edit-taxonomy.ts, classify-edits.ts).
  • Evals with a cascade judge (lib/cmo/jobs/eval).
What to add, in order
  • No AI Slop and the fix to x-writing.md, which teaches the hooks No AI Slop bans.
  • Platform profiles as data, so one idea becomes a post for X, Threads and LinkedIn.
  • Voice samples from the founder's own approved posts, the best voice data we will ever have.
  • Captions and video words for Studio: captions per platform, YouTube title and description, the video brief, slide text.

Design: one pipeline, many platforms and kinds

Keep the X pipeline's shape for every kind of text. What changes per platform is data (the platform profile); what changes per founder is data too (voice samples, corrections). The prompt stays stable, which keeps the prompt cache warm.

Scroll sideways to see the whole diagram.

Who writes the video script. Writer owns words that go out as text; Studio's Director owns the beats of a long take. For a video, Writer hands Studio a video brief (angle, three hook options, key points, the call to action) and later writes the captions, title and description from the finished video. The Slideshow squad's writer step calls Writer's write_slides capability, so slide text passes the same checks.

Over MCP the founder's Claude can write instead of our model, as checkRubric() in steps.ts already allows; code checks stay the last gate.

6

Voice

Sources, best first
  1. Approved as is (similarity ≥ 0.95): the founder chose these words.
  2. Edited, then approved: the final text is the founder's own writing; the edit mode says what was wrong.
  3. Pasted samples at onboarding (optional): a few posts or paragraphs, as humanizer suggests.
  4. The strategy's voice sentence and words to avoid (today).
How they are used
  • The 5–8 most recent samples for the target platform go into the prompt as examples of voice, never as text to copy.
  • Samples are data inside tags, like documents (lib/cmo/untrusted.ts).
  • The founder sees and can remove samples on the Brand page.
  • No fine-tuning: few-shot examples from the founder's own words are enough and stay current.

Build phases

  1. W0 · No AI Slop. The skill, the banned list in code, the checker criteria, the x-writing.md and fake-draft fixes, evals before and after. Small, no migration.
  2. W1 · Platform profiles + Threads and LinkedIn posts. The data file; one idea becomes per-platform versions; checks per profile.
  3. W2 · Voice samples. From approved and edited posts; optional pasted samples; shown on the Brand page.
  4. W3 · Words for Studio. Captions per platform, YouTube title and description, the video brief, slide text, as Studio's Shorts and Slideshow squads arrive.
  5. W4 · Threads on X and long drafts. When a founder asks for them.
