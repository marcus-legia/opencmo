Writer: the words department

Status: built (main at 4f70a59, 2026-11-08). Designed 2026-10-26, built in phases W0–W4 (P1–P6) and the CMO review (#169–#180). Markdown twin for agents: writer.md; the two say the same thing. Parent pages: ai-cmo.html, brain.html, studio.html.

Writer writes every word that goes out: posts, threads, captions, video titles and descriptions, the brief a video starts from, the text on slides; in the founder's voice, from the founder's documents, through code checks and a second look before a card. In the owner's sketch of 2026-11-08 Writer is step 2: words are written, and approved, before anything is built from them.

§4

Design: one pipeline, many platforms and kinds

Scroll sideways to see the whole diagram.

  • Inputs, all feeding the writer: brief (work order: idea, angle, platforms, due day); documents (product, strategy with voice and words to avoid, competitors); voice notes; corrections (tier 0 memory); platform profile (data).
  • Chain: Writer (LLM; one agent per platform profile; 3 versions) → code checks (length, words to avoid, numbers; no links; hashtags per profile) → checker (Claude Haiku in a separate context; facts and voice; no-ai-slop as advice, not a gate) → a failed check goes back to the writer once → card (versions side by side; approve, edit, skip).
  • Learning loop, for every kind: approved as is → a voice note; edited → similarity + edit mode; skipped → memory; repeated edit modes → a correction card, read first next time.
  • Per-platform and per-founder differences are data; the prompt stays stable (prompt cache).
  • Who writes the video script: Writer owns words that go out as text; Studio's Director owns long-take beats. For a video, Writer hands Studio a video brief (angle, three hook options, key points, call to action) and later writes captions, title and description from the finished video. The Slideshow squad's writer step is Writer's write_slides.
  • Over MCP the founder's Claude can write instead (checkRubric() in steps.ts); code checks stay the last gate.

§5

no-ai-slop in Writer: guidance, not a rule

Decided 2026-10-26, and since 2026-11-05 a product rule: every word a person reads or hears goes through no-ai-slop. It is advice the writer reads, never a code check on a draft and never a gate that drops one.

LayerWhat
Skilllib/cmo/skills/no-ai-slop.md (MIT notice in LICENSE.md and THIRD_PARTY_NOTICES.md): editing principles and patterns to watch, without its chat questions or output format; embedded as NO_AI_SLOP in every writing prompt (posts, captions, briefs, slides, plans, replies, scripts, on-screen text)
Check on promptslib/cmo/skills/no-ai-slop.check.ts fails when a prompt that writes for a reader does not carry the guide; a new writing prompt is added there
Checkerreads the same guide as advice; may suggest a fix in its one round; a pattern alone never drops a version
Founder's voice winswhen voice notes show the founder writes a certain way, that beats the guide
Measureapprove-as-is rate and edit modes (cmo:eval, production)

Code checks stay only for facts and product rules: length, the strategy's words to avoid, numbers that must be in the documents, no links, hashtags per platform profile.

§6

Voice: learned into memory, not fixed

Decided 2026-10-26: no fixed "write like you" profile and no samples at onboarding. A founder's style changes; the brain keeps learning it from what the founder approves and how they edit, and newer notes outweigh older ones.

  • Feeds: posts approved as is (similarity ≥ 0.95); edits before approval (final text + edit mode such as WRONG_VOICE, TOO_SALESY); skip reasons.
  • Kept as short voice notes in cmo_memories (topic post, with importance) and the Sunday post lesson (cmo_lessons), both built; notes expire or lose weight so a new style replaces an old one within weeks; a repeated change becomes a correction card (brain tier 0); no fine-tuning, no fixed sample set.
