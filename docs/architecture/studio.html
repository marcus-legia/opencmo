Studio: the video department

Studio is the editor plus the Video agent team. It makes every visual deliverable: AI long videos, shorts cut from a finished edit, slideshows and post images, and it hosts the founder's hands-on edits of their own video. This page says what Studio is today, what others teach, and how it becomes a department the brain can brief. Markdown twin for agents: studio.md. Parent pages: ai-cmo.html, brain.html. Status: proposed.

Verdict

Studio is the most built department
  • An editor with one write path (editor-core ops), one renderer for preview and export, server export on Modal.
  • Four built squads of the Video agent team: long take (/video), intro, explainer and 3D, B-roll and images; 12 slash commands; 26 models in the catalog.
  • Three callers already share it: the Assistant chat, MCP, and (proposed) the brain.
What it needs to be a department
  • One Studio adapter, extracted from MCP's studio group, that the brain and MCP both call.
  • A "finished" state for an edit and export of a named timeline.
  • Three new squads: Shorts, Slideshow, Post image.
  • A look check that draws frames from the full-size export before the founder sees a card.

Ranked by the editor strategy: Shorts first (every OpenCMO video becomes 3 shorts for X, Shorts, Reels, TikTok), then Slideshow (cheap, popular on TikTok and LinkedIn, no video model needed), then Post image. Each lets us make the next marketing post end to end in the editor.

Naming trap found in the code

The table clips is the editor's project unit (one uploaded or blank edit, kind full | blank), and the code calls a project a "clip" everywhere (clip_id, ClipDocument). Calling the short videos cut from an edit "clips" too would mix the two in every query and prompt. Proposal: in code they are shorts (kind = short, op make_short, order cut_shorts); the user-facing copy stays "cut short clips from your finished video".

Design: one adapter, seven squads, shared tools

Every squad has the same shape, learned from Agent Opus and already used by the long take: an LLM step, a code reviewer that sends it back once, a builder that writes ops, and a renderer. The adapter is the only door, so the brain, the founder and MCP get the same squads, cards and prices.

Slideshow squad

A slideshow is a document of timed slides, so it needs no new runtime: the same ops, renderer and export. It reuses what onboarding already knows (product, audience, voice) and the Brand Kit.

Inputs and rules
  • Brief from the week plan, the marketing documents, the Brand Kit, captured pages of the founder's own site (capture_page).
  • Writer: 5–10 slides; slide 1 is the hook; one idea per slide; the last slide is a call to action; the No AI Slop rules apply (Writer department).
  • Visuals: the founder's own screenshots and captured pages first; an AI image only when a slide needs one, moderated, never with text inside the image.
  • Text is always an editor layer, so it stays editable and sharp.
Two outputs from one document
  • MP4 for Reels and Shorts: timed slides with transitions and an optional music bed.
  • PNG set for TikTok photo mode (up to 35 images, cover index, recommended music by TikTok), Instagram and LinkedIn carousels: one still per slide drawn by the same renderer.
  • Both formats share approval: one card, the slides side by side.
Decided 2026-10-26: one editor core, a Slides view

Owner's choice, following Canva (one editor for presentations and video, different views) and CapCut (photo mode and templates inside the main app). Not a second editor: a separate page with its own renderer would rebuild render, export, Brand Kit, captions and moderation, and CLAUDE.md allows one editor runtime.

  • Entry: "New" offers New video and New slideshow. A slideshow is a project of a new kind slideshow (the clips table allows full | blank today, so one migration adds it).
  • Slides view by default: a slide strip on the left (add, delete, drag to reorder), the frame in the middle, text, image, colour and per-slide duration on the right. The timeline is hidden; "Timeline" switches to the full editor for transitions and music.
  • Same document underneath: each slide is a timed span on one timeline, changed only through new editor-core ops (add_slide, move_slide, set_slide_duration…), so the Assistant and MCP get them too. MP4 through render_document; the PNG set is one still per slide from the same renderer.
  • From the brain: a slideshow lands in the Approval inbox; the card allows quick text edits per slide, and "Open in Slides" for more.
  • Size: Slides view, slide ops and PNG export M; entry and project kind S.

8

Post image squad

For a post that needs a picture, a cover for a video, or a YouTube thumbnail (roadmap E4.2). Prefer a frame of the founder's own video or a captured page with a title layer; generate an image only when none fits. Aspect per platform; text is a layer; Brand Kit fonts and colours. The /image command already makes the image; what is new is the recipe, the title layer and the deliverable.

Build phases

  1. S0 · Finish the long take. Its open Tasks 0, 1 and 8 and the release: one real 60 s OpenCMO video on production. Everything after this assumes the long take works for real.
  2. S1 · Studio adapter + finished state + named-timeline export. Extract MCP's studio group into lib/departments/studio, MCP keeps its behaviour; add "finished" (card 3 or a button) and export of a timeline that is not the open one.
  3. S2 · Shorts squad. Segmenter, clip editor, reviewer, make_short, render; first on AI long videos (beats already known), then on the founder's own finished edits.
  4. S3 · Slideshow and post image squads. MP4 + PNG set from one document.
  5. S4 · Look check + Studio evals. The vision judge on the existing look function; measures on the dashboard.

S0 is on the editor roadmap already. S1–S2 are editor work that makes marketing videos (every video → shorts), so they pass the spearhead test; they also line up with E4.1 (export set) and E4.5 (hand-off to Post). The brain meets Studio at the brain's B3, which needs S1.
