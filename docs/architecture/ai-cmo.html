ARCHITECTURE.md §11 summarises the same system. The order of work follows the owner's decision of 2026-11-08: the AI CMO first, the editor last (plan §2).

OpenCMO is one CMO brain that plans and dispatches work to seven departments, with the founder approving everything that goes out. The departments are the product, so the system is shaped around them, not the other way round. It stays one system: Vercel + Supabase + Modal.

    • Sales: sales_scan, score and draft, subreddit rules (own) · ScrapeCreators (buy)
    • Studio: editor-core ops, render_document, the Studio adapter and its squads (own) · fal.ai, ElevenLabs (buy)
    • Approval: checker scores first; one inbox, approval snapshot, in-app notices and web push (own) · email via Resend (buy)

  4. Data spine (Supabase): work_orders, deliverables, approvals, schedule_slots, social_accounts (Zernio ids, no tokens), credit_orders; and editor_projects, tasks, credit_ledger, Storage. Every write goes through a gated RPC (ownership, credit hold, limits).

The Modal MCP app has its own secret and a user JWT. Bought: Claude, fal, ElevenLabs, ScrapeCreators, Resend, Zernio.

  9. Browser → platform: intent link, the founder taps post (fallback with no connected account).

§4b

Moderation is Creem's

Owner decision D8 (2026-11-05). We write no content policy of our own and run no LLM check on prompts.

StepWhereWhat
Prompt, on the weblib/generate/moderation.ts, in createGeneration before credits are heldEvery image and video prompt (and our own renderer's on-screen text) goes to Creem's Moderation API. flag blocks like deny. If Creem cannot answer, the request is refused
Prompt, again on the workeropencmo/ai/moderation.py check_promptThe same Creem call, because create_generation is also callable straight through PostgREST
Outputopencmo/ai/moderation.pyThe image, or three video frames, go to Claude Haiku (vision) against Creem's rules quoted as they are (packages/contracts/creem-policy.json), and to fal's NSFW classifier as a second opinion. Blocked → the task fails, the credits come back, the file never reaches the bucket

Voice, music and sound prompts are not screened (Creem does not require it); voices stay premade, with no cloning, dubbing or lip-sync. Production enables AI images and video only with a live Creem key and a working output review (moderationReady).

§4c

What providers cost us: the spend ledger and the Costs page

20270104010000_provider_spend.sql (plan).

  • provider_usage: one row per paid provider call (CMO model calls, ScrapeCreators lookups, fal and ElevenLabs media), in micro-USD per founder, priced when written. Model calls are priced from agent_model_prices, the same list the Assistant is charged from; provider_prices holds the other units. A call with no price row is stored with priced = false, never guessed. fal and ElevenLabs are recorded unpriced today (plan S3.3 adds their prices).
  • provider_spend_cap: a daily safety cap per founder ($5 by default); read paths ask provider_spend_allowed before they spend.
  • The Costs page (app/app/settings/costs/page.tsx) is for the owner only (app_owners, provider_spend_report): seven days of spend per provider, and the switches from lib/ops/switches.ts: UI v2, email, web push, Zernio posting and webhook, Creem, the social reader (ScrapeCreators), the Modal clock, MCP and the global kill switch. A switch only says whether a variable is set: it does not call the provider, so a bad key shows green. There is no row at all for Anthropic, fal or ElevenLabs, which is why the Anthropic 401 of 2026-11-08 showed nowhere. Plan S3.1 adds a live check per provider.

§9

Six rules

  1. One kind of work order. Everything the brain hands out is a work_orders row with a kind, a brief, a credit budget and a machine-readable failure. A new feature is a new kind + handler.
  2. One data spine. Every output is a deliverables row (kind, ref_kind, ref_id), one set of statuses.
  3. One capability registry. Brain, buttons, Assistant and MCP call the same tools; no private path for the brain.
  4. Gates live on the write path. Ownership, credit holds and limits run in database RPCs; Creem moderation on web and worker. Every caller passes through them.
  5. The brain never posts. Publish is reached only through Approval; the time and the account are part of what is approved, and any change needs a new approval.
  6. Every department has an eval, measured by how often the founder approves as is.

§11

Order of work

Ranked by the CMO loop (owner, 2026-11-08): does it make the loop of §2 work for a paying founder, end to end? Editor work comes after.

  1. Paid-first entry and the first week within minutes (done: S2.1–S2.3; the rail follows the loop, components/shell-v2/nav.ts).
  2. /video hidden and the week plan without AI video (done: S2.4–S2.5).
  3. No dead ends, one card per job, Sales behind a card (S2.6 partly done; S3.5–S3.6).
  4. Providers you can see: Costs page rows, deploy check, priced fal and ElevenLabs spend (S3.1–S3.4).
  5. Owner: the Anthropic key everywhere, Creem live key and review, Zernio checks, Vercel Hobby.
  6. Then fewer cards a week, one Assistant, and the editor (their own plans).

History. The 2026-10-25 order (Writer and No AI Slop → the spine → registry and Studio takes a script → Approval inbox, notifications, Schedule → Studio slideshow and clips → Publish on Zernio) was built in full in P1–P6.
